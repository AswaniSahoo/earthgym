# The decisions, in plain words

One row per record in `docs/decisions/`. For each: what it decides, why, and the main
alternative. Where a record names no alternative, the row says so. Write agree, change (and
what) or question (and what) in the last column.

| record | what it decides | why | main alternative | agree / change / question |
|---|---|---|---|---|
| 0001 | The ClimaQA audit, which checks the dataset for leaks and errors, uses only Python's built-in tools. | The data is six small files; nothing else is needed, and there is nothing to install or keep patched. | None recorded; a data library such as pandas would be the obvious one. | |
| 0002 | Inspect (from the UK AI Security Institute) runs the ClimaQA question sets against models and keeps the logs. Its built-in graders were later replaced by the shared rules of 0004. | Its logs are reproducible, and the inspect_evals Register, a public list of evals, asks for an Inspect task and logs from two models. | None recorded. | |
| 0003 | Each environment is a package for Prime Intellect's verifiers library (version 0.4.0), with its data inside, so it runs offline. | The environments are meant for RL training and for Prime Intellect's Environments Hub. | None recorded. | |
| 0004 | One file per environment holds the prompts and the grading rules, and both Inspect and verifiers use it. | The two tools graded 14 of 38 test replies differently; two graders that disagree cannot be compared. | Let each tool keep its own built-in grader. | |
| 0005 | ClimaQA's fill-in-the-blank (cloze) answers stay exact-match. A domain expert reviews the flagged items and writes lists of accepted answers for a later version; no AI judge grades replies. | Many cloze "misses" are acceptable wordings, but an AI judge makes the reward inexact, costs a call per reply and can drift when its provider updates it. | An AI judge model, or rewarding multiple choice only. | |
| 0006 | The weather scores (RMSE, ACC) are re-implemented with numpy, line by line from WeatherBench 2's code, and zarr reads the data. | WeatherBench 2's own package pulls in heavy libraries (apache_beam, jax), and WeatherBench-X brings one that conflicts with Inspect. | Install weatherbench2 or WeatherBench-X. | |
| 0007 | An ERA5 task: forecast pressure or temperature 24 to 72 hours ahead from one grid cell's recent history. The reward grows with how much the forecast beats the better of two simple guesses (no change, and the long-term average); copying either earns 0, and a small floor stops a near-perfect simple guess from inflating the reward. | It tests forecasting skill, graded the way forecasters grade forecasts. The floor rule was set during the build, before I reviewed it. | Tasks that ask the model to compute forecast scores from data: exact, but mostly arithmetic. | |
| 0008 | TypeSafe's Jev model would re-sort the 83 rows of the ClimaQA review sheet as a third reader; it never enters a reward and is capped at $0.10. It is built and tested, but not run: it needs a key I do not have. | The two earlier sorts were both made by AI models; a third reader measures how far to trust them. | None recorded; the expert review of 0005 is the human check. | |
| 0009 | An IBTrACS task asks one exact question about one storm: its accumulated cyclone energy (ACE), its peak hurricane category, or its hours at hurricane strength, with the counting rules in the prompt. | A different skill from the forecasts, an exact grader, and real traps, such as the extra 3-hourly rows that double ACE if counted. | Wind forecasts for storms, which would repeat the ERA5 design. | |
| 0010 | Every paid run uses one model, Claude Sonnet 5.5, through Anthropic's Batch API at half price, within $20 in all, each run after a small probe of its cost. No Vertex AI or Gemini calls. | My choice of model and budget. The Gemini run on Vertex was projected above its token guard and stopped. | Gemini 3.8 Flash on Vertex AI, dropped. | |
| 0011 | The 300 IBTrACS items: 100 storms per question from the 1980 to 2025 seasons, exact answers, ACE at one decimal as NOAA reports it. | One decimal matches NOAA and keeps the runs comparable. | ACE to two decimals, which would catch more misread winds; kept for later. | |
| 0012 | The heat-insurance plan: questions about a policy that pays when a weather station reads above a threshold, and the heat it misses for the policyholder (basis risk). The counting code must first reproduce the National Weather Service's published Phoenix heat counts. | Real heat-insurance programs work this way, and no benchmark covers them. | Indian data, for heat insurance in India: left out for now, since IMD names no licence, the GSOD readme forbids passing on non-US derived products, and ERA5 daily statistics need an account. | |
| 0013 | The 300 heat items, 2015 to 2024: the policy's station at a Phoenix-area airport, the insured site in the hotter city core; each question asks trigger days, payouts or missed days, with an exact whole-number answer. | With the hottest station as the policy's station almost no hot day is missed, so the policy's station is a cooler airport. | Phoenix Sky Harbor as the policy's station, the first choice, dropped for that reason. | |
| 0014 | Every environment package is built with one exact version of its build tool, hatchling 1.33.0. | A build tool that floats changes the built packages over time; the repo pins everything that can move. | Whatever version is newest at build time, as before. | |
| 0015 | The code is under the MIT License; the data keep their sources' terms. | My choice; the record gives no further reason. | None recorded. | |
| 0016 | One rule for answer lines in every environment (the answer on the last line, nothing after it, finite numbers only). ACE pays only its one-decimal rounding. Cloze matching keeps minus signs, decimal points and operators. Checks refuse broken inputs. | The Codex review found the parsers differed and some accepted wrong answers, for example "-2" matching "2". Re-grading every logged reply changed no score. | Keep each environment's own parser. | |
| 0017 | Each environment splits its items into train and test so that items sharing data (one storm, one season, one week of weather) stay on one side; about one group in five goes to test. | Without it, a model trained on one item could learn another's answer, and no held-out evaluation was possible. | A random split by item, which would leak shared data. | |
| 0018 | The exact IBTrACS file the items came from is attached to the repo's `data-v1` release, so the items can be rebuilt after NOAA updates it. The GHCN-Daily station files are not published. | IBTrACS's terms say its data is "open for distribution" for research; NCEI's own pages name no licence for GHCN-Daily. | Publish both files, or neither. | |
| 0019 | For every reported run, a compact file of each item's id, parsed answer, reward and tokens is in the repo, and every report is rebuilt from it in a test. | The raw logs are not in git, so nobody else could check a published number. | Publish the full logs instead, with every reply; they are planned as a release asset too. | |
| 0020 | The repo and its package are renamed from rlenv to earthgym. | "rlenv" is taken on PyPI and says nothing about the subject; "gym" is the field's word for task suites, and earthgym was free. | earth-rlvr, the reviewers' runner-up name. | |
| 0021 | Each environment checks that its own correct answer earns the full reward; items that fail are dropped. That dropped 72 of the 720 ERA5 items, where the floor of 0007 kept even a perfect forecast below full marks. | An item that a perfect answer cannot win is broken for training, and verifiers expects this check. | Keep the 72 items and change the reward formula so a perfect forecast earns 1 there, which would change 0007's rule. | |
| 0022 | Two small open models, Qwen3.5-2B and IBM Granite 4.0 H-1B, answer every item of all four environments 8 times, with thinking off and up to 4,096 tokens a reply. The reports give the mean reward, how many items get different rewards across the 8 tries, and how often 1 try or any of 8 is right. | One paid model answering once cannot show whether an environment gives a training signal: training compares several tries at the same item, so it learns only where they differ. | A Kaggle GPU from the start: faster, but a larger setup. Decision 0025 moved there later. | |
| 0023 | A tools mode for the IBTrACS environment: the storm's rows leave the prompt, and the model reads them with one read-only database (SQL) tool, within 14 model turns. Both harnesses send the same conversation. Every environment now defaults to running no code the model writes. | With all its data in the prompt, a task is one reply. Fetching the rows makes several steps, and the transcript shows how the model read the data. | A Python or shell tool, so the model could compute in code. That runs what the model writes, which needs a sandbox. | |
| 0024 | A small training run (GRPO) of Qwen3.5-2B on ClimaQA's multiple-choice items, on a Kaggle GPU, 250 steps and one seed, with the reward on train and held-out items before and after. A rule fixed before the results chose the task: the most reward variation among tasks whose replies fit the training limit. | It tests whether an environment gives a small model something to learn from, and it is reported whether or not the reward moves. | Plain TRL and PEFT without Unsloth: fewer parts, but Unsloth was the one path with a documented run of this model on a free GPU. | |
| 0025 | The small-model runs move from this laptop's GPU to Kaggle's free T4 GPUs, on one Kaggle account, with private kernels and datasets. The models, runner and settings stay. A stopped session resumes where it left off. | I took the laptop's GPU back for my own work, with that run hours from its end. | vLLM on the T4s, faster in batches, but Unsloth's docs say its vLLM path does not support Qwen3.5 GRPO. | |
| 0026 | A second computation of every bundled heat and storm key, from the rendered prompt alone, written by a separate AI agent that never saw the keys or the code that made them. All 600 keys match. A test also pins how many keys each wrong rule would change. | The item tests rebuild the items with the code that made them, which shows the items are consistent, not that the keys are right (the Codex review's finding 8). | HURDAT2, NHC's own archive, as a second source for the storm keys. It would also test the rows, but it needs a new pinned file, a parser and a match from each storm to its IBTrACS SID. | |
| 0027 | The repository is public since 2026-11-13, with the heat items, which carry four GHCN-Daily stations' daily maxima for 40 station-seasons. The raw station files stay unpublished. The heat items' terms are stated as two facts (NCEI names no licence; NOAA's NODD listing gives CC0-1.0, its reach to NCEI's own files unknown), and the draft dataset card carries them. Amends 0018. | My choice ("flip", then "yes for all"); the record gives no further reason. | Leave the heat items out, the other option the draft dataset card named. | |
